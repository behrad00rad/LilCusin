# Rating intent, compact controls and Close — 2026-10-17

The user clarified that sending a song to rate must not trigger audio recognition or waste processing, and requested smaller Details controls, button colors, and Close on search results. This supersedes the earlier automatic fingerprint fallback for untagged audio files.

## Implemented

- Telegram audio uploads default to rating, with ratings immediately visible after catalogue identification. Missing tags prompt for artist/title; they do not trigger Shazam, media downloads, or FFmpeg. Music documents (audio MIME type or supported music extension) use the same route.
- `/rate` prompts for a song or accepts a replied audio/music document. The main menu explicitly says Rate a song. `/recognize` remains the explicit fingerprint action for unknown audio; voice/video/post identification remains available separately.
- Known local rating uploads skip background search warming and presentation enrichment. Catalogue lookup is still used when needed to establish the song identity; file tags do not bypass identity matching.
- Song-list rows use three controls: a blue download action, compact rating heart, and compact Details ellipsis. Details no longer occupies half a two-column row. Rating views contain the four rating choices, Similar, and Close, without unnecessary download/version controls for a song the user already sent.
- Telegram-native preset styles provide blue primary actions, green positive ratings, and red negative/Close/Cancel controls. The Telegram client determines exact widths, heights and theme-adjusted colors; no custom pixel dimensions or RGB values are claimed. Reference: https://core.telegram.org/bots/api#inlinekeyboardbutton
- Search candidate lists have a dedicated Close button, bound to the owner, search revision and message. Closing invalidates that result without cancelling another search or delivery. Closing a card/list removes its grant without deleting ratings. Recording-source choices have request-scoped Close.
- Main help/welcome copy explains rating versus identification. Existing Mini App assets and production remain untouched. Earlier chat messages retain their old keyboards; `/start` and newly generated results display the new controls.
