## Findings

1. **Delivery is inconsistent across surfaces.** chat_handlers.py supports Get song; miniapp.py emits external listen_url links and has no delivery request/status route. web/app.js follows those links. locales.json still teaches users to visit Lil Bro, press Send, and return. This is a capability gap, not merely outdated styling.
2. **The main task is subordinated to training.** interactions.present sends a rating card after identification. chat_ui.card_keyboard places ratings first and Get song last. Recommendation lists have four or five buttons per track across five tracks; rating requires a separate card. A song search should lead with the song and audio action.
3. **Onboarding delays value.** handlers.start invokes three-step taste setup before its guide fallback. Returning users reaching that fallback see the guide again. Mini App boot branches to setup before the main view, and otherwise can show a three-step modal. Setup is skippable, but still interrupts the first task. Guide dismissal awaits a preferences write and can fail to close on a network error.
4. **Search has a completion barrier.** workflow.search_title gathers remote provider results before returning even when local candidates exist; additional hint searches and lyric discovery can follow. Parallel calls help, but one slow provider still delays the complete response. Exact latency is unmeasured.
5. **Busy-state handling blocks unrelated actions.** lifecycle.PrivateActions holds one user lock over the handler, rejects new events while locked, and adds a three-second cooldown to selected recommendation navigation. Cancellation also traverses this middleware, so it can be rejected during an in-flight handler. Background delivery does not hold this lock for its entire job.
6. **Delivery has head-of-line blocking.** get_song.run awaits one execute call before selecting the next job. execute awaits artwork loading before its cached-delivery check. This structurally permits unrelated requests and cache hits to wait behind slow work; impact requires measurement.
7. **Chat accumulates workflow debris.** Pending search notices are dismissed, but candidates, cards, lists, guide steps, queue notices, and version prompts frequently use new messages. Old controls can expire and then instruct the user to restart. Recovery loses task context.
8. **Mini App startup is serial.** Locale loading, Telegram initialization, preferences, and initial view loading are awaited in sequence. API calls default to a 35-second timeout. Telegram SDK probing can wait up to five seconds when absent. Timeout budgets are not measured normal latency.
9. **Rating disrupts browsing.** Mini App ratings sit behind a details disclosure; rating then replaces the card through a serialized replacement queue. Replacement offers freshness but can remove the user's reference point and adds another recommendation round trip.
10. **Visual hierarchy is weak.** The source combines a repeated brand/hero, generic dark panels, small artwork, symbolic navigation icons, and many similar controls. The For You hero spends prime space sending users elsewhere to search. These are design assessments from markup/styles; phone appearance, contrast, overflow, and RTL were not browser-tested.
11. **Localization has holes.** New Get song, version, queue, and delivery notices contain hard-coded English while older UI uses translated strings. Critical recovery/status paths need the same translation discipline as navigation.

## Proposed flow

Start -> search immediately, send a clip, or request recommendations.
Search -> local/cached results immediately -> enrich with bounded remote results.
Result -> Get song as primary action; Similar and More as secondary actions.
Get song -> cached audio immediately, or one persistent status with Cancel -> audio.
Ambiguous recording -> concise version choices before download.
After delivery -> optional Love / Like / Not for me and More like this.
Recognized clip -> show identified track and proceed under an explicit, consistent delivery policy.
Taste setup -> optional progressive personalization after first value.
